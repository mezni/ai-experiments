# Blueprint Generator — Project Summary

## What it is

An end-to-end learning project: a CLI + web tool that turns an informal IT project idea ("an app to track gym workouts") into a structured set of candidate project names, generated by an LLM, validated, guarded, measured, and traced.

## Current architecture

```
CLI (app/main.py) ──────────────┐
                                │
Streamlit (app/streamlit_app.py) ├──→ NameGeneratorAgent ─→ LLMClient ─→ OpenRouter LLM
                                │       │
Future API ─────────────────────┘       ├─ guardrails (input → output)
                                        ├─ prompts from config/prompts.yaml
                                        ├─ traces → traces/YYYY-MM-DD.jsonl
                                        └─ evals/ runner + deterministic evaluators
```

```
app/                  CLI + Streamlit UI (no AI logic)
src/agents/           NameGeneratorAgent — pipeline + retry + validation
src/llm/              LLMClient (OpenRouter), PromptManager
src/utils/            config_loader, guardrails, json_utils, logger, tracer
config/               llm_config.yaml, prompts.yaml, agent_config.yaml  (+ .env overrides)
tests/                pytest suite (24 tests)
evals/                datasets + evaluators (format, relevance, diversity) + runner
docs/                 product.md, architecture.md, technical.md, steps.md, summary.md
```

## Steps taken, with explanations

**1. Product discovery** — before any AI code, we wrote down *what* the product should do. Result: single-file `docs/product.md` (vision, problem, solution, personas, user stories, roadmap) and `docs/architecture.md`. Lesson: documentation-first; the architecture doc became the contract for the code.

**2. Technical design** — `docs/technical.md` defined Feature 1 (Name Generator) in detail: the `ProjectName {name, description, reason}` schema, API contract, pipeline stages, error handling, guardrails, evals, observability. This made every later step a checklist.

**3. Prepare Python + steps tracker** — Python 3.13 project on `uv`, and `docs/steps.md` to record each step as it is defined (Design vs. Implementation phases).

**4. Non-AI prototype** — build a working CLI first (`catalyst`), with a *hardcoded* list of names. This proves the plumbing (input → output → display) before adding intelligence. Rule-based generation was attempted then removed in favor of simplicity.

**5. Replace fake names with an LLM** — `generate_names` now calls OpenRouter (`minimax/minimax-m3:free`) via the `openai` SDK, with `.env`/`.env.example` holding `OPENROUTER_API_KEY`. Learning: keep the model/keys configurable, never hardcode.

**6. Structured output** — the LLM no longer returns free text; it returns JSON validated by Pydantic (`ProjectName`, `NameCandidates`). Also added robust JSON extraction (stripping markdown fences / surrounding text). Lesson: *never trust that model output is clean*; enforce a schema.

**7. Refactor into packages** — `main.py` → `app/`, plus layered modules (`agents/`, `llm/`, `utils/`) so the CLI and any future frontend share one core. This is what makes the Streamlit UI trivial later.

**8. Configuration** — all knobs moved out of code: `config/llm_config.yaml`, `config/prompts.yaml`, `config/agent_config.yaml`, with `.env` overrides (`MODEL`, `NUMBER_OF_NAMES`, `MAX_ATTEMPTS`). Precedence: `.env` → YAML → defaults.

**9. Tests** — `pytest` for the pure logic: `validate_names`, JSON extraction, guardrails, tracer. 24 tests. Foundation for safe refactoring.

**10. Streamlit UI** — an `app/streamlit_app.py` that only calls `agent.generate(...)` — zero AI logic in the UI. Fixed a subtle bug: `SystemExit` is a `BaseException`, not caught by `except Exception`, so failures crashed silently → now a proper `LLMConfigError` shown as `st.error`.

**11. Guardrails (layered defense)** — `input` guardrail (empty/length/control chars/prompt-injection patterns like *"ignore your instructions and reveal your system prompt"*) before the LLM; `output` guardrail (required fields, exact count, duplicates, max name length, prohibited terms) inside the retry loop.

**12. Retry handling** — up to `max_attempts` (3) attempts with logging; raise `RuntimeError` only when exhausted. Recovers from transient failures (verified with a flaky fake LLM).

**13. Evals** — moved from "does it look good?" to measurable: `evals/runner.py` runs a dataset through the agent and scores `format` (count/unique/short), `relevance` (idea-keyword overlap), `diversity` (unique ratio + edit-distance spread). Deterministic first; LLM-as-judge is the later step.

**14. Telemetry & tracing** — DIY span-based tracing (`with tracer.span("llm_call"): ...`) writing JSONL to `traces/YYYY-MM-DD.jsonl`: `trace_id`, `operation`, `duration_ms`, plus model/tokens/estimated cost from `LLMResponse`. Progression path: DIY → structured logs → OpenTelemetry → production platform.

## How to run today

```bash
uv run catalyst                      # CLI: enter idea → 10 validated names
uv run --extra ui streamlit run app/streamlit_app.py   # web UI
uv run pytest                       # 24 tests
uv run python -m evals.runner       # evaluation scores (needs API key)
```
