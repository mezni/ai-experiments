# ADR-002: Full snapshots per index version, append-only registry

- **Status:** Accepted
- **Date:** 2026-09-01

## Context

Index versions must be reproducible and rollback-able. Two designs were
considered:

1. **Metadata-only versioning** — point a "current" pointer at a buckets of
   deltas; old vectors stay in place. Cheap to write, expensive and risky to
   restore.
2. **Full snapshots** — each index version owns its complete set of vectors
   and chunk metadata in a dedicated Chroma snapshot. Rollback is a physical
   restore.

## Decision

Use **full snapshots per version**:

- Every build writes a fresh snapshot under `indexes/chroma/versions/<version>/`
  with its own Chroma collection (`docs_<version>`).
- Rollback repoints `current_version` at a stored snapshot; retrieval switches
  to that snapshot's collection with no re-embedding.
- The index registry (`indexes/index_registry.json`) is **append-only**:
  existing version records are never mutated. Only the `current_version`
  pointer may change.
- A failed snapshot build must not mutate the registry or the pointer; the
  snapshot directory is the commit boundary.

## Consequences

- Storage grows one full copy per version; acceptable for the MVP, mitigated
  later by a snapshot retention policy.
- Rollback is safe and fast: the target collection already exists on disk and
  is validated before the pointer moves.
- Unchanged documents are carried into a new snapshot from the previous one
  without new embedding requests, preserving the RAGOps 1 idempotency
  guarantee.
